I.MX6ULL Linux 的 VS Code 开发环境

1. 独立配置文件
在 VS Code 左下角齿轮 -> 配置文件 -> 导入配置文件，选择：
/Users/yang/Documents/ChatGPT/linux/.vscode/IMX6ULL.code-profile
创建并使用 I.MX6ULL Linux 配置文件。它只推荐 C/C++ 和中文界面扩展。
如果已经有同名配置文件，切换到该配置即可。
STM32 配置用于 STM32 项目；本目录使用 I.MX6ULL Linux 配置。

2. 格式化
保存 .c/.h 文件时自动格式化。
手动格式化：Shift + Option + F。
采用 Microsoft C/C++ 扩展自带的 clang-format。
根目录 .clang-format 决定风格：4 空格、Linux 风格大括号、100 字符行宽。
格式化调整排版，不负责修复语法、补全函数或解决逻辑问题。

3. 编译当前文件
打开你要编译的 .c 文件，先 Command + S 保存，再 Command + Shift + B。
默认任务：IMX6ULL：编译当前 C 文件。
任务调用 Ubuntu 中的 arm-linux-gnueabihf-gcc，生成 ARM32 Linux 程序。
当前版本面向单个 .c 文件的学习程序；多个 .c 文件组成的工程后续再用 Make/CMake 管理。
输出：build/active/相对源码路径去掉.c
例如 apps/light-monitor/test.c -> build/active/apps/light-monitor/test。
报错中可点击文件路径和行号回到源码。

4. 部署运行
Command + Shift + P -> 任务: 运行任务 -> IMX6ULL：编译并在板子运行当前 C 文件。
这一步会先编译，编译成功后由 Mac 的 ADB 复制到开发板，并运行。
板上路径：/root/embedded-project/current-program。
默认连接设备 100ask_IMX6ULL，需要板子已上电并连接 USB OTG。
编译失败会终止任务，不会继续部署旧程序。
此任务不会刷写系统；程序如果持续循环，按 Ctrl+C 停止。
原来的 Ubuntu 示例、光线参考程序任务仍在任务列表中，可手动选择。

5. 三种终端
终端右上角下拉菜单可以选择：
Mac · zsh：Mac 本机，用于 git、adb、limactl。
Ubuntu · embedded-dev：Linux 虚拟机，用于编译工具和 Linux 命令。
开发板 · ADB：通过 adb shell 进入开发板。
默认新建的是 Mac 终端。

6. 代码补全和头文件
项目 .vscode/c_cpp_properties.json 让 Mac 编辑器按 ARM32 Linux 目标解析代码。
本地 Clang 只辅助编辑和语法分析；真正生成板子程序的是 Ubuntu 的 GCC。
Linux ARM32 头文件来自 Ubuntu，缓存于 build/vscode-sysroot，不提交到 Git。
首次搭建已同步。换电脑或清理 build 后，运行：
./scripts/vscode-imx6ull.sh prepare
也可通过任务 IMX6ULL：准备代码补全头文件 执行。
当前配置针对 Linux 用户态 C 程序；内核源码需要自己的内核构建配置。
当前项目没有配置 F5 远程断点调试；本次配置的是编辑、格式化、编译与 ADB 运行。

7. 终端等价命令（Mac）
./scripts/vscode-imx6ull.sh build "$PWD/apps/light-monitor/test.c"
./scripts/vscode-imx6ull.sh run "$PWD/apps/light-monitor/test.c"
实际项目目录应先 cd /Users/yang/Documents/ChatGPT/linux。
学习中的 test.c 若尚未写完，报编译错误是正常现象，按报错逐步学习修正。
